# Reference Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the current editorial Flask pages with the approved dark chess-analysis Home and animated Information experiences while preserving real upload and live-result behavior.

**Architecture:** Render one shared `landing.html` shell for both `/` and `/analyses/<job_id>`, then mount the existing API/SSE behavior when a job ID is present or an upload succeeds. Keep Information server-rendered and drive its reveal stack with the shared animation module. No API, database, Kafka, feature, or model contract changes.

**Tech Stack:** Flask/Jinja, semantic HTML, plain CSS, ES modules, `IntersectionObserver`, `requestAnimationFrame`, Python `unittest`.

## Global Constraints

- `/analyze` redirects to `/`; `/system` remains the Information URL.
- Preserve form names `pgn_file`, `pgn_text`, and `lichess_url` and submit to `POST /api/analyses`.
- Preserve live status/game endpoints, source ordering, EventSource updates, filtering, pagination, verdict-first rows, clickable Details, and score explanations.
- Do not change PostgreSQL, Kafka, ingestor, PyTorch, XGBoost, or model preprocessing code.
- Use the existing isolated RGBA PNG assets; do not add gradients, `backdrop-filter`, external fonts, external JavaScript, or fake analytics.
- Honor `prefers-reduced-motion: reduce` and retain semantic keyboard behavior.
